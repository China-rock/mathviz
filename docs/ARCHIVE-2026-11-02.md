### 7. 启动崩溃：`act_render` 属性不存在（16:56）
- 现象：重装后每次启动弹「MathViz 崩溃：AttributeError: 'MainWindow' object has no attribute 'act_render'」，但程序照常能用。
- 根因：`_build_ui()` 里先 `connect(combo_quality.currentIndexChanged)`，紧接着从 QSettings 恢复画质，
  `setCurrentIndex` 触发信号 → `_apply_quality_ui()` 去改 `self.act_render` 文案，
  而该 QAction 要等更晚的 `_build_menus()` 才创建。**首次安装默认 480p 不触发；用户选过 720p/1080p 后每次启动必现**
  （设置存在注册表，重装不清）。
- 修法：恢复画质时用 `blockSignals(True/False)` 包住 `setCurrentIndex`；`_apply_quality_ui()` 再用 `getattr` 兜底。
- 回归：`tests/run_all_tests.py` 18 组全通过。

### 8. 渲染预检测（17:00）
- 动机：LLM 生成的脚本首渲失败是常态，而 manim 起进程到报错要 8 秒以上 ——
  必然失败的错误应该在**按下按钮那一刻**就说清楚。
- 新增 `_precheck(code, what)`（`app/ui/main_window.py`），渲染与快检之前各调一次：
  - 场景名对不上时自救：脚本里只有一个 `Scene` 子类就直接改用它（手抄脚本类名多是 `Demo` 而非 `KP*`），
    有多个 `Scene` 类则不擅自决定，交给人选。
  - 挡下四类必然失败：语法错、未找到 Scene 类、`MathTex/Tex` 里混非 ASCII（中文）、用了未定义的名字。
  - 弹窗给出精确行号 + 自动跳行 + 行号标红，并留「仍要渲染 / 回去改脚本」两个出口（不强拦）。
- 底层新增 `renderer.scene_class_names()`（对外口径，只认 `Scene`/`ThreeDScene` 子类）。
- 菜单「运行 → 🔍 预检测脚本（不渲染，先体检）」，快捷键 `Ctrl+Shift+V`（`Ctrl+Shift+P` 已被导出关键帧占用）。
- 测试：`tests/t_precheck.py`（10 项：探测口径 / 放行 / 改名自救 / 中文挡下 / 强制放行 / 语法错 / 未定义名 /

发布到 GitHub Release（仓库 `https://github.com/China-rock/mathviz`，tag 用 `v1.0.0`）：

```bat
rem gh 已装在 C:\Program Files\GitHub CLI\gh.exe（不在 PATH 里，用全路径或加进 PATH）
set "PATH=C:\Program Files\GitHub CLI;%PATH%"

rem 打 tag（v 前缀）+ 推代码
git tag -a v1.0.0 -m "MathViz v1.0.0"
git push origin main
git push origin v1.0.0

rem 建/改 Release 并换附件（--clobber 覆盖同名附件）
gh release create v1.0.0 "dist/MathViz-1.0-Setup.exe" -t "MathViz v1.0.0" -F notes.md
gh release upload v1.0.0 "dist/MathViz-1.0-Setup.exe" --clobber

rem 删旧 tag（1.0.0 → v1.0.0 改名用）
git push --delete origin 1.0.0
git tag -d 1.0.0
```

> 上传 221 MB 附件要几分钟，`gh release upload` 带 `--clobber` 才能覆盖同名旧附件。

## 五、环境坑（再遇到别重复踩）

- **manim 子进程的工作目录不能含空格**：否则 MiKTeX 的 `dvisvgm` 报 `Windows API error 87`，
  看着像 TeX 坏了。所以渲染固定在 `%LOCALAPPDATA%\MathVizWork`。
- 本机 `USERNAME` 环境变量是 `67676`，但用户目录是 `C:\Users\ChRis`，别用 `%USERNAME%` 拼路径。
- PyPI 直连 ~60 KB/s，装包一律加清华镜像；uv 同时只能跑一个进程。
- GUI 测试组会弹窗，`run_all_tests.py` 必须串行；与冒烟测试并行会互抢窗口导致误报。
