# MathViz

> 把课件 / 教材丢进去，AI 写出 Manim 脚本，渲染成数学动画视频。
> 面向高中与大学数学的可视化学习工具，Windows 桌面应用。

## 一、项目简介

**MathViz 解决的问题**：想看懂一个数学概念（比如 ε-δ 定义、割线逼近切线），
静态教材不够直观，自己学 Manim 又门槛太高。MathViz 把这三步合成一个窗口：
读你的课件 → 和 AI 确认要讲什么 → 自动生成并渲染出带中文解说的动画视频。

**工作流**：打开课件（或直接输入想学的知识点）→ AI 提取知识点 → 中栏对话确认「呈现清单」
→ 生成 Manim 脚本 → 渲染播放。
没有课件也能用：直接说"我想理解 ε-δ 定义"，AI 会给出呈现清单，确认后即可生成脚本。
脚本渲染失败时，程序会自动把报错回传给 AI 修复并重渲（最多 3 轮）。

**适合谁**：高中生 / 大学生做概念理解，老师批量做教学短片，任何想把数学"画出来"的人。

| 检查更新 | 帮助菜单一键检查，有新版本直接在程序里下载并静默安装（装完自动重启）；启动后也会安静查一次，不打扰 |

## 三、技术栈与环境要求

| 组件 | 必需 | 说明 |
|---|---|---|
| Python 3.12 | ✅ | manim 要求 ≥3.11，3.12 经过最多验证 |
| [uv](https://docs.astral.sh/uv/) | 推荐 | 依赖安装比 pip 快一个量级，用 pip 也可以 |
| LaTeX 发行版 | ✅ 渲染公式必需 | Windows 推荐 [MiKTeX](https://miktex.org/download)；Linux 用 TeX Live |
| ffmpeg | 自动 | 由 `imageio-ffmpeg` 提供内置二进制，无需手动安装 |
| DeepSeek API Key | ✅ | 在 [platform.deepseek.com](https://platform.deepseek.com/api_keys) 申请 |

技术栈：Python 3.12 · PySide6（Qt 桌面界面）· Manim CE（数学动画渲染）· DeepSeek API（脚本生成）· PyInstaller（打包）。

> **⚠️ MiKTeX 安装时务必勾选 "Always install missing packages on the fly = Yes"**
>
> 否则首次渲染公式时，MiKTeX 会弹出模态框等待确认，而渲染在无头子进程里进行——
> 那个框没人能看见，渲染会一直卡到超时。这是最常见的踩坑点。
> 不需要事先打开 MiKTeX Console，渲染时会自动调用；首次用到新宏包会联网下载，
> 那一次明显变慢（几十秒到几分钟都正常），不是卡死。

<details>
<summary>不想装 1 GB 的 LaTeX？</summary>

Manim 自 v0.19 起提供 Typst 渲染通道（`MathTypst`），`manim[typst]` 自带编译器，不需要系统 TeX。
但本项目默认让 AI 生成 `MathTex`（LaTeX）语法——AI 生成 LaTeX 的准确率明显更高。
Typst 建议仅作为无法安装 LaTeX 时的降级方案。

</details>

## 四、安装步骤

```bash
# 1. 克隆并进入项目目录
git clone <仓库地址> mathviz
cd mathviz

# 2. 建虚拟环境（本机没有 3.12 时，uv 会自动下载）
uv venv --python 3.12 .venv

# 3. 装依赖（国内建议加清华镜像）
uv pip install --python ".venv/Scripts/python.exe" \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
```

用 pip 也可以：

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
```

## 五、配置说明

只需配一样东西——DeepSeek API Key。三选一，优先级从高到低：

1. 环境变量：`DEEPSEEK_API_KEY=sk-...`
2. 项目根目录建 `.env`：`cp .env.example .env`，填入 `DEEPSEEK_API_KEY=sk-...`
3. Key 放在自定义名字的环境变量里时，在 `.env` 中登记变量名：
   `DEEPSEEK_API_KEY_ENV_NAME=你的变量名`

`.env` 已在 `.gitignore` 中，**不会**被提交。

### 环境变量一览

| 变量 | 作用 | 默认值 |
|---|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek API Key | 无，必需 |
| `DEEPSEEK_API_KEY_ENV_NAME` | 可选。指定存放 Key 的自定义环境变量名（写在 `.env` 中） | — |
| `MATHVIZ_WORK_DIR` | 自定义渲染工作目录，**路径必须无空格、无中文** | Windows 取 `%LOCALAPPDATA%\MathVizWork`，其他系统取临时目录下的 `MathVizWork` |

## 六、运行方式

Windows 上三种启动方式效果完全一样（都走 `pythonw`，全程不弹黑色终端窗口），区别只在「点哪个」：

| 入口 | 适合 | 说明 |
|---|---|---|
| **双击 `MathViz.exe`** | 日常 | 8 MB 原生启动器，可丢到桌面或固定在任务栏 |
| 双击 `run.bat` | 备用 | 会先闪一下 cmd 窗口再把活交给启动器 |
| 双击 `MathViz.vbs` | 兜底 | 启动器被杀软误杀 / 被删时用；纯脚本，任何 Windows 都能跑 |

> **`MathViz.exe` 不是完整程序**，它只是把 `.venv` 里的 pythonw 拉起来跑 `app.main`，
> 必须和 `app`、`.venv` 在同一个目录；单独复制到别处会弹窗提示，不会一声不响地失败。

命令行启动（其他平台 / 排错用）：

```bash
.venv/Scripts/pythonw.exe -m app.main   # 无控制台
.venv/Scripts/python.exe  -m app.main   # 带控制台，看报错用
```

> 无窗口模式下 `stdout / stderr` 接到 `logs/console.log`，未捕获异常写入 `logs/crash.log`
> 并弹系统提示框——不会因为"静默"而查不到原因。

## 七、使用示例

### 快速上手（6 步出片）

1. 把课件**拖进左上角的投放区**，或点击它从资源管理器选择
   （没有课件可跳过，直接输想学的知识点；第一次试用可以点「**文件 → 打开示例课件**」，
   一键载入内置的《微分中值定理》，不需要自己准备文件）
2. 左上角先选**学科**，然后点「提取知识点」，AI 列出适合可视化的知识点；
   **双击某个知识点会送入中栏对话**
3. 在中栏「内容自定义与工作确认」里与 AI 敲定「呈现清单」
   （要写公式就点输入框下方的「**f(x) 公式**」按钮，不用写 LaTeX）
4. 点【确认，生成脚本】→ 脚本出现在右侧编辑器（可手动微调），
   渲染按钮旁实时显示**预计成片时长**（目标 45~80 秒）
5. 选**画幅**与**画质**，点「🎬 渲染（当前画质）」→ 右下预览区自动循环播放
   （就这一次想出 1080p 用 `Ctrl+Shift+R`，不改画质选择）
6. 想省时间：先点「🔎 版式快检」看几张定格图，或勾「✂ 只渲第 a~b 段」只渲改动的那几步
7. 手动改过脚本后，用「运行 → 🔍 预检测脚本」（`Ctrl+Shift+V`）先体检一遍：
   语法错、场景名对不上、`MathTex` 里混了中文、用了没定义的名字 —— 这几类问题跑起来必然失败，
   预检测会直接跳到出错那一行标红；点「渲染」时也会自动先过一遍体检
8. 想把几个知识点揉进同一支动画：左栏 **Ctrl 点选 / Shift 连选**，点「🧩 整合」——
   AI 会先判断它们是递进、并列还是因果，排出讲解顺序，再给一份统一的呈现清单；
   「生成脚本」永远跟着**当前对话**走，切回历史对话也不会串台

**一次做一整套**：知识点列表右上角的「🗂 批量」把勾选的知识点排队：
逐个生成 → 静态检查 → 渲染 → 成片体检，串行出片、随时可停。
建议先 480p 批量审片，挑中的再单独高清重渲。

### 最小可运行示例

不配课件、不开对话，直接验证渲染管线是否通畅：

```bash
.venv/Scripts/python.exe -m manim -ql demo_scene.py
```

`demo_scene.py` 是仓库自带的示例场景，渲出的视频在 `media/` 下；
也可以点「文件 → 打开示例课件」（等价于导入 `samples/` 里的文件）走完整流程。

> 示例课件随程序一起打包，打包版的路径是 `<安装目录>\_internal\samples\`，
> 所以「打开示例课件」这个菜单项在安装版里同样可用。

### 文件能力边界（重要）

本工具只读文件里的**文字层**，读不到"画在图上的字"：

| 文件 | 能不能用 | 怎么办 |
|---|---|---|
| Word / PPT 原生文本、LaTeX、md | ✅ | — |
| 文字可选中的 PDF（导出型、可复制） | ✅ | — |
| 扫描件、拍照生成的 PDF | ❌ 字在图里，没有文本层 | 先 OCR，或用可复制的源文件 |
| 整页由图片拼成的 PPT | ❌ 同上 | 换成文本版，或 OCR 后再导入 |
| PPT 里插的高清配图/视频 | ➖ 不影响文本提取，也不参与分析 | — |

大文件不用担心"体重"：几百 MB 的 PPT 往往只是图片多，解析按"非媒体部分"的体积判定
（实测 448 MB 的 PPT 提取文本仅需 2.3 秒）。单文件文本超过 60000 字符时，
调用 AI 前会自动截断并在日志里提示。

## 八、常见问题 FAQ

**渲染卡住不动 / 报 LaTeX 错误**
先确认 MiKTeX 勾了自动装包（见第三节）。程序会把报错自动回传给 AI 修复，最多重试 3 轮；
仍失败时看右侧日志面板的报错尾部。

**成片背景是黑色的**
不是故障，是 Manim 的默认画布底色（3Blue1Brown 式惯例）。想改白底，
在脚本开头加一行 `config.background_color = WHITE` 再渲染（旧片需重渲）。

**视频太短 / 节奏太快**
节奏交给 AI（提示词写死「中等偏慢」，目标 45~80 秒），渲染前就能看到「预计成片 ~XX 秒」。
要调，直接在对话里说"第 3 步太快了"，勾「🛠 代码修改模式」即可，不会重写整支片子。

**画面里的文字重合、糊成一团**
先用「🔎 版式快检」看定格图；仍有问题时勾「🛠 代码修改模式」说一句
"第 20 秒的解说和公式叠在一起了"，AI 会按布局规则重排。

**改内容还是改代码？**
- 画面效果不对（布局、节奏、配色）→ **代码问题**，勾「🛠 代码修改模式」
- 想改"讲什么"（增删知识点、调整顺序）→ **内容问题**，保持开关关闭正常发消息

**安装时能自己选路径吗**
可以。安装向导里的「选择安装位置」页可改到任意目录；升级安装同样会显示这一页，
默认填上次装的位置，回车沿用、改掉即换地方。
程序的数据（成片、缓存、Key、日志）都在 `%LOCALAPPDATA%\MathViz`，
所以装到 `Program Files` 还是 D 盘，读写行为完全一样。

**找不到 `latex` 或 `ffmpeg`**
程序会兜底探测常见安装路径；仍失败就把它们所在目录加进 `PATH` 后重启应用。

**以前的成果找不到了**
看左栏下方的「历史成果（双击载入）」列表——所有生成过的条目都在，
🎞 表示有成片、📄 表示只有脚本，双击即载入，全程不调用 AI。

**渲染时弹出黑窗**
正常情况下不会有；若出现，说明手动改动了启动方式。
程序已通过 `sitecustomize.py` 注入消除 manim 子进程及其孙辈（latex / dvisvgm）的控制台窗口。

## 九、测试方式

仓库自带 16 组自动化测试（核心逻辑 + GUI 冒烟，offscreen 模式）：

```bash
# 在项目根目录执行；GUI 组会短暂弹窗，请串行运行、不要两份同时跑
.venv/Scripts/python.exe tests/run_all_tests.py
```

- 每组用独立子进程 + 900 秒超时，实时打印 `[OK]` / `[FAIL]` 与关键断言摘要
- 结果写入 `tests/test_results.json`（退出码、耗时、输出尾部、是否 Traceback）
- 全部通过时末行显示 `16 组：16 通过，0 失败`；串行总耗时约 1~1.5 分钟

单跑某一组：

```bash
.venv/Scripts/python.exe tests/t_bugfixes.py
```

用户侧的功能自检：「帮助 → 关于」会显示 Manim 版本、LaTeX 路径与渲染工作目录，
配合第七节的 `demo_scene.py` 可以快速确认环境完好。

## 十一、已知限制

- 中文字体写死 `Microsoft YaHei`（Windows 自带）。macOS / Linux 需在 `app/core/prompt.py` 中换成系统已安装的字体。
- MiKTeX 路径探测是 Windows 逻辑；其他平台依赖 `PATH` 中的 `latex`。
- 渲染工作目录必须无空格、无中文——只要 manim 子进程的当前工作目录含空格，
  MiKTeX 的 `dvisvgm` 就会以 `Windows API error 87` 退出（看着像 TeX 装坏了，其实是路径问题）。
  本项目已把渲染子进程的工作目录固定到无空格目录来绕开它。
